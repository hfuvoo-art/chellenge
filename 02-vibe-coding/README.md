# Вайб-кодинг: «Цифровой деканат будущего»

Концепт личного кабинета студента «Мой деканат · Деканат, который отвечает» для MGIMO×AI Challenge 2026.
Не официальный сервис вуза, все данные вымышленные. Бриф: [[02-vaib-koding-cifrovoy-dekanat]]. Идея и план: [[vaib-koding-ideya-i-plan]].

## Что есть (ядро брифа + свои идеи)
1. **Вход и профиль:** логин и пароль, ФИО, факультет, направление, курс, группа.
2. **Сегодня:** ближайшая пара с таймером, смена аудитории и отмены сверху, риски, готовые справки, дедлайны, объявления.
3. **Расписание:** день и неделя, точки на днях с изменениями, перенос и отмена видны сразу.
4. **Учёба:** средний балл, прогноз оценки по баллам, светофор по предметам, «сначала это», прогноз стипендии с причиной риска, зачётка за прошлые семестры, страница предмета с работами, сроками и контактом преподавателя.
5. **Заявки:** 7 видов справок и заявлений, статус как у доставки (подана → в работе → готово), история, справка с QR-кодом и публичной проверкой подлинности `/verify/<код>`.
6. **Уведомления:** объявления, изменения расписания, статусы заявок, дедлайны, фильтры.
7. **Документ к заявке:** к пересдаче, академическому отпуску, индивидуальному плану и повышенной стипендии можно приложить справку (PDF, JPG, PNG до 2 МБ). Тип проверяется по содержимому, файл видят только студент и офис.
8. **Кабинет учебного офиса:** берёт заявку в работу, закрывает или отклоняет с причиной, меняет аудиторию и время, отменяет пару, публикует объявление. Студент видит изменения через несколько секунд без перезагрузки.
9. **Помощник деканата:** отвечает по вымышленным положениям вуза со ссылкой на пункт (пункт раскрывается), знает данные только текущего студента, на вопрос о чужих данных отвечает отказом, при отсутствии ответа говорит «не нашёл», сам заполняет черновик заявления. Отправляет студент.
10. **Вход и «О проекте»:** страница входа объясняет проект, тестовые аккаунты нажимаются, открытая страница `/about`.
11. **Сброс демо:** данные возвращаются к исходным каждую ночь в 04:00 МСК и по кнопке в кабинете офиса (аккаунты сохраняются; `DEMO_RESET=off` отключает).
12. **Чат по заявке:** студент задаёт вопрос в своей заявке, сотрудник отвечает из кабинета, студент получает уведомление. В очереди офиса есть отметка «Вопрос» и отдельный фильтр.
13. **Тёмная тема:** включается сама по настройке устройства. Справка с QR-кодом остаётся белым листом.
14. **Настройки уведомлений в профиле:** студент выбирает, какие уведомления получать.

## Как устроено
- Next.js 16 (App Router, серверные компоненты и Server Actions), TypeScript, SQLite (better-sqlite3).
- Все данные читаются на сервере по сессии. Адрес вида `/requests/1031` ищется по номеру **и** владельцу: чужая заявка даёт 404.
- Пароли: bcrypt-хэш. Сессия: случайный токен 32 байта в httpOnly-cookie, в базе только его SHA-256, срок 7 дней. После 5 неверных попыток входа за 10 минут для пары «IP + логин» разрешена одна попытка в минуту.
- Server Actions защищены от CSRF проверкой Origin (встроено в Next.js). Заголовки: CSP, X-Frame-Options, Referrer-Policy.
- Ключ ИИ (необязательный) только в переменных окружения сервера. Черновик заявления собирает код по правилам, модель не может создать заявку сама.
- Шрифт Inter (OFL 1.1) раздаётся с нашего сервера, без запросов к Google. Иконки нарисованы вручную. Библиотеки: next, react (MIT), better-sqlite3 (MIT), bcryptjs (MIT), qrcode (MIT), zod (MIT).
- Масштабирование: база вынесена в `lib/`, запросы параметризованы, перенос на PostgreSQL не меняет страницы.

## Запуск локально
```bash
cd 02-vibe-coding/app
npm install
npm run dev        # http://localhost:3000, база создаётся сама в data/
npm test           # проверки доступа и данных
npm run seed       # пересоздать вымышленные данные
```
