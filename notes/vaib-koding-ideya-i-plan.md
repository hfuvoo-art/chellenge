## Идея: «Деканат, который отвечает»
Кабинет студента, где всё сходится на главном экране «Сегодня», а деканат отвечает сразу, без очереди.

1. **Главная «Сегодня»:** ближайшая пара (аудитория, преподаватель), перенос ярко выделен, дедлайны, статусы заявок, свежие объявления. Нужное за одно касание.
2. **Расписание:** сегодня и неделя, изменения и переносы видны сразу.
3. **«Как у меня дела»:** оценки и зачёты, светофор по предметам, риск по сессии и стипендии, что сдать в первую очередь.
4. **Справки и заявления:** заказ в 2 касания, статус как у доставки (подана → в работе → готова), справка с QR-кодом проверки.
5. **Уведомления:** новости деканата, напоминания о дедлайнах, перенос пары.
6. **Кабинет сотрудника деканата:** очередь заявок, смена статуса, публикация объявления и переноса пары. Студент видит изменения сразу.
7. **ИИ-помощник (YandexGPT, ключ только на сервере):** отвечает на вопросы по вымышленным положениям вуза с цитатой пункта, сам заполняет заявление по просьбе в чате, объясняет «как у меня дела». Видит только данные текущего студента через сервер.

Сквозной сценарий для демо: сотрудник переносит пару → у студента уведомление и обновлённая главная → студент спрашивает помощника «что мне нужно для пересдачи» → помощник заполняет заявление → сотрудник одобряет → статус «готово».

Свой бренд-концепт без логотипа вуза, плашка «Концепт для конкурса MGIMO×AI Challenge, не официальный сервис».

## Стек
- Next.js (App Router, TypeScript) + PostgreSQL + Drizzle ORM.
- Сессии в httpOnly-cookie, пароли argon2/bcrypt. Все данные берутся по сессии, а не по id из адреса.
- Docker Compose на виртуальной машине Yandex Cloud, HTTPS через Caddy, деплой GitHub Actions. Секреты в GitHub Secrets и `.env` на сервере.
- Вымышленные данные через seed-скрипт: 2+ студента с разными факультетами и успеваемостью, 1 сотрудник.
- Дизайн по скилу `site-design`, шрифты и иконки с открытой лицензией (список ведём).
