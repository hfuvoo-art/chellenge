# Стратег с реестром доказательств

Агент ведёт руководителя цифрового продукта от размытого запроса до проверенных продуктовой и коммуникационной стратегий. У каждого факта есть источник, локатор и дословная цитата; выводы и гипотезы агента фактами не становятся, это проверяют скрипты `tools/check.py`, а не обещания модели.

## Шпаргалка для маркетолога

Терминал не нужен.
- **Открыть.** Claude: вкладка Code, выбор папки проекта `strateg-agent`. Cursor: File → Open Folder → `strateg-agent`.
- **Первая фраза:** «Новый проект: <ваш вопрос>». При первом запуске агент один раз предложит установить библиотеки (2–3 минуты): ответьте «да». Ключ Yandex AI Studio нужен позже, как его получить, см. ниже; до точки 2 можно и без него.
- **Что будет.** 6 шагов: постановка, сбор материалов, исследование, варианты, стратегия, после решения. Каждое сообщение агента начинается строкой `Шаг N из 6 · … · сделано … · дальше …`. Агент остановится и спросит 3 раза:
  1. после постановки: подтвердите задачу и вопросы (или поправьте);
  2. после вариантов: выберите вариант или попросите доработать;
  3. после стратегии: примите её или укажите, что поправить.
  Ответ нужен по строке «Ваш ход: …» в конце сообщения.
- **Команды.** В Claude: `/status` (где мы), `/new` (новый проект), `/continue` (продолжить). В Cursor и других средах те же слова обычным текстом: «статус», «новый проект», «продолжи». Ещё можно написать «стоп», «назад к шагу N», «поправь …».
- **Остановиться и продолжить завтра.** Напишите «стоп»: агент сохранит состояние. Завтра откройте ту же папку и напишите «продолжи».
- **Где результат.** Стратегия: `projects/<проект>/export/strategy.html`. Панель проекта: `projects/<проект>/panel.html` (её делает отдельная задача).

Ниже путь через терминал, он нужен разработчику.

## Для разработчика: запуск через терминал

Нужен Python 3.11 или новее. Все команды ниже запускайте из папки `strateg-agent`.

## Как получить ключ Yandex AI Studio

Нужны два значения: **API-ключ** (секрет) и **ID каталога** (`folder_id`). Оба кладутся только в `.env` (он в `.gitignore`): не в чат, не в коммиты, не на скриншоты.

1. Войдите в Yandex Cloud: https://console.yandex.cloud (Яндекс ID). Если платёжного аккаунта нет, создайте его (нужна карта). Есть ли стартовый грант, смотрите в консоли при создании платёжного аккаунта.
2. Откройте AI Studio: https://aistudio.yandex.cloud/platform/ и выберите каталог (по умолчанию `default`).
3. Нажмите **«Создать API-ключ»** (справа вверху), укажите описание и срок действия, **«Создать»**. Создастся сервисный аккаунт с ролью `ai.editor` и ключ с областью `yc.ai.languageModels.execute`: этого достаточно. Для создания нужна роль `resource-manager.admin` на каталог (у владельца облака она есть). **Секретный ключ показывают один раз**, сразу вставьте его в `.env`.
4. **ID каталога**: в консоли Yandex Cloud откройте каталог и скопируйте «Идентификатор» (строка вида `b1g…`).

### Какие переменные `.env` обязательны

Шаблон — `.env.example`; значения читает `tools/llm.py`.

| Переменная | Нужна | Что вписать |
|---|---|---|
| `LLM_API_KEY` | да | секретный ключ из шага 3 |
| `LLM_PROJECT` | да | ID каталога из шага 4 |
| `LLM_BASE_URL` | да | `https://llm.api.cloud.yandex.net/v1`; запасной адрес из туториала Yandex: `https://ai.api.cloud.yandex.net/v1` |
| `EXTRACT_MODEL` | да | `gpt://<ID каталога>/aliceai-llm-flash` |
| `PRO_MODEL` | да | `gpt://<ID каталога>/yandexgpt-5.1` |
| `CRITIC_MODEL` | да для критика с ключом | `gpt://<ID каталога>/yandexgpt-5.1`; свои `CRITIC_BASE_URL`, `CRITIC_API_KEY`, `CRITIC_PROJECT` нужны, только если критик ходит в другое место (иначе берутся `LLM_*`) |
| `MAIN_MODEL_FAMILY`, `CRITIC_MODEL_FAMILY` | нет | для Claude Code: `claude` и `yandexgpt`. Только проверка независимости критика: совпали, статус покажет жёлтую строку; пусто, проверка не выполняется |
| `JUDGE_MODEL` | нет | судья слепого сравнения с обычным чатом; пусто — не используется |
| `AGENT_ROUTE`, `LLM_TIMEOUT_S` | нет | маршрут среды (`claude-code`, `opencode`, `cursor`, `other`; пусто определяется само) и таймаут запроса в секундах |

`yandexgpt-5-lite` не используйте: модель отключается 15.11.2026, дешёвая роль `extract` работает на `aliceai-llm-flash`. Цены моделей, поиска, курс и дата их проверки лежат в `config/prices.yaml`: оттуда считается стоимость, порядок цены прогона смотрите в `python tools/status.py` у своего проекта. Список моделей Yandex: https://aistudio.yandex.ru/docs/ru/ai-studio/concepts/generation/models

Адрес API и передача ID каталога через `OpenAI-Project` проверяются первым `ping` (шаг 4 ниже): если ответ не `LLM OK`, попробуйте запасной адрес.

## Быстрый старт с ключом (основной путь)

Ключ нужен для извлечения утверждений и для критика другого семейства моделей: так дешевле и независимее. Также нужна среда с агентом, например подписка Claude Code (оплачивается отдельно от ключа; расход модели среды агент записывает в журнал отдельной статьёй).

1. Создайте окружение и поставьте зависимости.
   - Windows (Git Bash): `python -m venv .venv`, затем `source .venv/Scripts/activate`
   - Windows (PowerShell): `python -m venv .venv`, затем `.venv\Scripts\Activate.ps1`
   - macOS и Linux: `python3 -m venv .venv`, затем `source .venv/bin/activate`
   - затем `pip install -r requirements.txt` и `pip install -r requirements-dev.txt` (тесты)
2. Скопируйте шаблон настроек: `cp .env.example .env` (в PowerShell: `Copy-Item .env.example .env`). `.env` — это файл, а не папка; в git он не попадает.
3. Впишите в `.env` значения из раздела «Какие переменные `.env` обязательны». Ключи пишите только в `.env`.
4. **Проверка установки.**
   - `python -m pytest -q` — тесты зелёные (нужен `requirements-dev.txt`; сеть и ключ тестам не нужны).
   - `python tools/llm.py ping --role extract` — ответ `LLM OK · …`. `--role pro` и `--role critic` проверяют остальные модели. Ответ про ключ или модель: сверьте `.env` с таблицей выше.
   - `python tools/lock.py --verify` — `OK: правила совпадают с rules.lock.`
5. Запустите Claude Code в папке `strateg-agent`. Активировать окружение необязательно: скрипты и хуки сами находят `.venv` (`tools/venv_boot.py`). Агент прочитает `AGENTS.md`, а хук покажет статус проекта.
6. Напишите первое сообщение агенту своими словами, например: «Новый проект: продуктовая стратегия eSIM для путешественников. Нужно решить, какой продукт запускать и как о нём говорить; рынок и ограничения уточните у меня.» Агент создаст проект, сам прочитает `playbooks/1-frame.md`, соберёт `brief.md` и вопросы и остановится на точке 1, чтобы вы подтвердили постановку.

## Путь без ключа (запасной)

Если ключа нет, выполните шаги 1 и 5 выше, а `.env` и `ping` пропустите. Скрипты `extract.py`, `critic.py` и `respond.py` с флагом `--emit-prompt` печатают промпт и путь для ответа; модель среды (Claude Code) кладёт ответ JSON-файлом, а `--apply <файл.json>` применяет его с теми же проверками. Что меняется:
- в `state.yaml` появляется `degraded: env-model`, в статусе красная строка `[КРАСНАЯ]`;
- критик — модель среды в чистом контексте, статус показывает жёлтую строку `[ЖЁЛТАЯ]`: независимость только за счёт чистого контекста;
- правила доказательств и 11 проверок `check.py` те же.

## Что где лежит

| Файл или папка | Зачем | Что сломается без него |
|---|---|---|
| `AGENTS.md` (`CLAUDE.md` ссылается на него) | роль агента, 6 шагов, 3 точки человека, список команд | агент не знает процесса и границ |
| `playbooks/` | по одному файлу на шаг: вход, действия, выход, критерий готовности | шаг делается по памяти, без критериев |
| `methods/` | методики: постановка, JTBD, варианты, позиционирование, экономика, план проверки, интервью, UX | нет шаблонов анализа |
| `rules/`, `prompts/` | правила доказательств, безопасности, стиля; промпты извлечения и критика | пропадает разделение фактов и выводов, нет защиты от команд в источниках |
| `rules.lock` | хеши запертых файлов (`rules/`, `prompts/`, `methods/`, `AGENTS.md`, `CLAUDE.md`, `check.py`, `lock.py`) | подмену правил не заметить; сверка — `python tools/lock.py --verify` |
| `tools/` | скрипты: проекты, загрузка источников, извлечение, реестр, проверки, критик, статус | нет доверия: проверки делают они |
| `tools/hooks/` и `.claude/settings.json` | 4 хука Claude Code: статус при старте, вопрос перед правкой запертых файлов, запись `tool` и `search` в журнал | нет статуса при старте, запертые файлы правятся без вопроса, журнал неполный |
| `.claude/skills/`, `.claude/agents/` | 6 навыков-обёрток, команды `/status`, `/new`, `/continue` над playbooks и субагент `ux-observer` (читает скриншоты, только `Read`) | нет вызова шагов по названию и изолированного разбора скриншотов |
| `config/prices.yaml` | цены моделей и поиска; `null` — цена неизвестна | стоимость не посчитать, статус жёлтый |
| `personas/` | персоны модельных респондентов | `respond.py` не из чего строить |
| `projects/` | проекты: `brief.md`, `claims.jsonl`, `options.md`, `strategy.md`, `state.yaml`, `log.jsonl`; `CURRENT` — текущий | нет состояния и журнала |
| `evals/`, `tests/` | проверки инъекций, чисел и структуры; запуск `python -m pytest -q` | регрессии не заметны |
| `.env.example`, `.env` | шаблон настроек и ваш файл с ключом | без ключа работает только запасной путь |

## Шесть шагов и три точки человека

1. Постановка → 2. Сбор → 3. Исследование → 4. Варианты → 5. Стратегия → 6. После решения. Подробно — в `AGENTS.md` и `playbooks/`.

Человек нужен в трёх местах: подтвердить постановку (конец шага 1), выбрать вариант (конец шага 4), принять стратегию и закрыть замечания проверок (конец шага 5). Во всех остальных агент работает сам и задаёт не больше 3 вопросов за раунд.

## Продолжение после перерыва

Откройте Claude Code в этой папке (в другой среде скажите агенту прочитать `AGENTS.md`). Статус одной командой: `python tools/status.py` — шаг, что ждёт от человека, стоимость по 5 статьям, деградации, следующее действие. Другой проект: `python tools/project.py list`, затем `python tools/project.py use <имя>`. Выполненное не повторяется (`action_id` в `state.yaml`).

В другой среде (OpenCode, Cursor) попросите агента прочитать `AGENTS.md` — это общий вход; хуки и `ux-observer` есть только в Claude Code.
