# Стратег с реестром доказательств

Агент ведёт руководителя цифрового продукта от размытого запроса до проверенных продуктовой и коммуникационной стратегий. У каждого факта есть источник, локатор и дословная цитата; выводы и гипотезы агента фактами не становятся, это проверяют скрипты `tools/check.py`, а не обещания модели.

Нужен Python 3.11 или новее. Все команды ниже запускайте из папки `strateg-agent`.

## Быстрый старт с ключом (основной путь)

Ключ Yandex AI Studio нужен для извлечения утверждений и для критика другого семейства моделей: так дешевле и независимее.

1. Создайте окружение и поставьте зависимости.
   - Windows (Git Bash): `python -m venv .venv`, затем `source .venv/Scripts/activate`
   - Windows (PowerShell): `python -m venv .venv`, затем `.venv\Scripts\Activate.ps1`
   - macOS и Linux: `python3 -m venv .venv`, затем `source .venv/bin/activate`
   - затем `pip install -r requirements.txt` (для тестов ещё `pip install -r requirements-dev.txt`)
2. Скопируйте шаблон настроек: `cp .env.example .env` (в PowerShell: `Copy-Item .env.example .env`). `.env` — это файл, а не папка; в git он не попадает.
3. Впишите в `.env` ключ и модели: `LLM_API_KEY`, `LLM_PROJECT` (ID каталога), `LLM_BASE_URL`, `EXTRACT_MODEL`, `PRO_MODEL`, `CRITIC_MODEL`. Подсказки по каждой строке — комментарии в `.env.example`. Ключи пишите только в `.env`, больше никуда.
4. Проверьте связь: `python tools/llm.py ping`. Ответ `LLM OK · …` — всё работает; `--role pro` и `--role critic` проверяют остальные модели.
5. Запустите Claude Code в папке `strateg-agent` **с активным окружением**: хуки вызывают `python`, и это должен быть python из `.venv`. Агент прочитает `AGENTS.md`, а хук покажет статус проекта.
6. Напишите запрос руководителя своими словами. Агент создаст проект и начнёт с шага 1.

## Путь без ключа (запасной)

Если ключа нет, выполните шаги 1 и 5 выше, а `.env` и `ping` пропустите. Скрипты `extract.py`, `critic.py` и `respond.py` с флагом `--emit-prompt` печатают промпт и путь для ответа; модель среды (Claude Code) кладёт ответ JSON-файлом, а `--apply <файл.json>` применяет его с теми же проверками. Что меняется:
- в `state.yaml` появляется `degraded: env-model`, в статусе красная строка `[КРАСНАЯ]`;
- критик — модель среды в чистом контексте, статус показывает жёлтую строку `[ЖЁЛТАЯ]`: независимость только за счёт чистого контекста;
- правила доказательств и 11 проверок `check.py` те же.

## Что где лежит

| Файл или папка | Зачем | Что сломается без него |
|---|---|---|
| `AGENTS.md` (`CLAUDE.md` ссылается на него) | роль агента, 6 шагов, 3 точки человека, список команд | агент не знает процесса и границ |
| `playbooks/` | по одному файлу на шаг: вход, действия, выход, критерий готовности | шаг делается по памяти, без критериев |
| `methods/` | методики: постановка, JTBD, варианты, позиционирование, экономика, план проверки, интервью, UX | нет шаблонов анализа |
| `rules/`, `prompts/` | правила доказательств, безопасности, стиля; промпты извлечения и критика | пропадает разделение фактов и выводов, нет защиты от команд в источниках |
| `rules.lock` | хеши запертых файлов (`rules/`, `prompts/`, `methods/`, `AGENTS.md`, `CLAUDE.md`, `check.py`, `lock.py`) | подмену правил не заметить; сверка — `python tools/lock.py --verify` |
| `tools/` | скрипты: проекты, загрузка источников, извлечение, реестр, проверки, критик, статус | нет доверия: проверки делают они |
| `tools/hooks/` и `.claude/settings.json` | 4 хука Claude Code: статус при старте, вопрос перед правкой запертых файлов, запись `tool` и `search` в журнал | нет статуса при старте, запертые файлы правятся без вопроса, журнал неполный |
| `.claude/skills/`, `.claude/agents/` | 6 навыков-обёрток над playbooks и субагент `ux-observer` (читает скриншоты, только `Read`) | нет вызова шагов по названию и изолированного разбора скриншотов |
| `config/prices.yaml` | цены моделей и поиска; `null` — цена неизвестна | стоимость не посчитать, статус жёлтый |
| `personas/` | персоны модельных респондентов | `respond.py` не из чего строить |
| `projects/` | проекты: `brief.md`, `claims.jsonl`, `options.md`, `strategy.md`, `state.yaml`, `log.jsonl`; `CURRENT` — текущий | нет состояния и журнала |
| `evals/`, `tests/` | проверки инъекций, чисел и структуры; запуск `python -m pytest -q` | регрессии не заметны |
| `.env.example`, `.env` | шаблон настроек и ваш файл с ключом | без ключа работает только запасной путь |

## Шесть шагов и три точки человека

1. Постановка → 2. Сбор → 3. Исследование → 4. Варианты → 5. Стратегия → 6. После решения. Подробно — в `AGENTS.md` и `playbooks/`.

Человек нужен в трёх местах: подтвердить постановку (конец шага 1), выбрать вариант (конец шага 4), принять стратегию и закрыть замечания проверок (конец шага 5). Во всех остальных агент работает сам и задаёт не больше 3 вопросов за раунд.

## Продолжение после перерыва

Откройте Claude Code в этой папке (в другой среде скажите агенту прочитать `AGENTS.md`). Статус одной командой: `python tools/status.py` — шаг, что ждёт от человека, стоимость по 5 статьям, деградации, следующее действие. Другой проект: `python tools/project.py list`, затем `python tools/project.py use <имя>`. Выполненное не повторяется (`action_id` в `state.yaml`).

В другой среде (OpenCode, Cursor) попросите агента прочитать `AGENTS.md` — это общий вход; хуки и `ux-observer` есть только в Claude Code.
